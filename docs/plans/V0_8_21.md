# v0.8.21 — superseded draft (MEL-602)

This draft was never published. Its tag and artifacts remain unchanged. The
full Windows gate exposed a real refusal/expiry race after packaging started.
The corrected production release continues in [V0_8_22.md](V0_8_22.md); the
passing unchanged qualification below is retained there.

Owner requirement: the native phone must send and receive promptly after resume
or a network handover, without resetting identity/history, losing queued sends,
or repeating work. A timeout must not leave both directions stuck on a dead
connection. Keep the implementation small and event driven.

Concrete acceptance: with an established real TLS/HTTP2 push connection, silently
break the old route while new TCP connections work. A network-change event (or
an ordinary request timeout) must retire the stale connection; the next send and
incoming message must use the healthy route with original durable IDs intact.
No pin, signature, workspace identity, permission, or receipt check is relaxed.

## Evidence and limits

Released v0.8.20, phone `admin/android-phone-3`, not revoked. Read-only relay
evidence around 18:20 Kyiv: phone offline; silent stream lease closures at
18:07:33 and 18:09:44; 21 incoming ciphertext copies in custody; no phone sends
in the bounded interval after 18:00. Laptop sends/receives successfully.
The screenshots show profile lookup deadline and `/v1/version` HTTP2 response
header timeout. This is broader than one send preflight.

Independent GPT-6.1-sol test reproduces stale connection reuse after a route
blackhole. A fresh transport succeeds; repeated old-transport calls time out.
This establishes a recovery defect, not the exact physical phone's initiating
network event. Current Android has no default-network callback and retains its
transport across stop/resume; stream watchdog may wait 270 seconds.

No live phone/desktop restart, grants, queue purge, relink or task replay.
v0.8.20 emulator checks proved stored-data preservation, not live connection
recovery. Do not claim physical-phone timing from emulator or source tests.
