## Narrow implementation boundaries

**B1/B2: recover the actual failure.** Start from the retained evidence and an
isolated affected profile/app environment. Record exact artifact and loaded
library versions for crashes; instrument the first invalid operation where
possible. A successful unrelated Xvfb quit, forced renderer kill, suppressed
notification or global GPU-disable default cannot qualify B1. Identify whether
B2 fails in browser storage, package data, metadata or bridge handling before
choosing recovery. Repair/rebuild only damaged skin storage with verified bytes;
failed repair retains usable data and reports an actionable error. No blanket
app-storage reset, enrollment reset or automatic trust of a changed package.

**B3/B4: review the authority change before implementing it.** Moved placement
needs verified organization evidence bound to the exact original content and
reviewed selection. A display label or incoming topic field grants nothing.
Concurrent moves, omitted evidence, changed keys and revoked participation fail
closed without silently expanding context. List editing preserves the existing
signed chain and current manager checks; adding to a list cannot enroll someone
in chats, disclose history or grant task permissions. Old readers wait for their
own compatible copies without vetoing other participants. Append any required
SQL step; never rewrite a shipped step or bypass version validation.

**B5/B6/B7: derive words and actions from persisted facts.** Cover native human,
native agent and browser move events, Main/named destinations, rename and
linked-device replay. B6 reuses exact handling/decision/report authority: a
later unrelated success is not proof that an older task completed. Preserve
original audit history, host/attempt bindings and truthful receipts. Repeated
handling/retry converges; it neither runs work nor closes a topic. Validate the
small resolution contract before introducing a new wire shape. B7 is display
formatting, with no changes to stored Markdown or timestamps.

**F1: one destination contract on the existing navigation path.** Links use
stable workspace/conversation/topic identity, including explicit Main; local
workspace aliases and changing loopback ports are not portable identifiers.
Links contain no auth/invite secret or private content and grant no access.
Opening validates the already-enrolled workspace and current access; it never
joins, approves, sends or fetches unauthorized history. Missing/inaccessible
targets get an honest outcome, not a different topic/workspace. Preserve drafts
and selected agent. Copy/open must survive topic rename, cold launch and two
devices using different local workspace aliases. Desktop, Android, browser and
all four skins share the same target semantics. Complete MEL-617 using existing
agent organization; no second organization or sharing service.

## Order, review and release gates

1. Refresh the exact current repros and retained crash/cache evidence. Establish
   the affected artifact/OS versions and availability of physical qualification
   devices early; record unavailable coverage plainly. No live request replay,
   grant changes, process interruption or destructive cleanup.
2. Fix B1–B7 with cheap focused before/after regressions. Review B3/B4 authority
   and B6 exact-resolution contracts before structural changes. F1 follows the
   move-destination contract; MEL-617 qualification reuses B3/B5/F1. Do the Q
   journeys on a concrete integrated candidate and batch confirmed failures.
3. Freeze stable integrated application and skin source. Retain valid evidence
   for unchanged code and rerun affected checks after a correction. Avoid full
   or platform suites per individual bug and do not increase their timeouts.
4. Complete `go vet ./...`, `scripts/race-shard.sh others`, all twelve
   `scripts/race-shard.sh client-K 12` partitions with 600-second bounds, actual
   IndexedDB/browser coverage, supported native OS and desktop/container gates.
   UI has its existing two partitions. Windows may use the existing disjoint
   A–G/H–Z selections at 1800 seconds. Count opt-in/platform skips separately.
5. Required mixed-version gate: fetch tags, use exact published v0.8.27 as the
   older release, and execute `TestMixedVersion` with compatibility required.
   Confirm per-recipient waiting and unchanged backlog delivery without live
   requests repeating; a skip is not a pass.
6. Required skins gate: pin `agentnet-skins/upstream.json` to the exact candidate
   and run `AGENTNET_SOURCE=<candidate repository> npm test` for the complete
   standalone/overlay collection. Exercise changed topic/link/status/list flows
   at desktop and phone widths in Comic, Classic, Holonet, Zoom and Pulp. Repair
   failing packages and publish the qualified collection, or revert the contract
   change. Each skin's `agentnet` field records the qualified release.
7. Verify all tag-built release assets and SHA256SUMS, including an original-key
   signed APK. Actual warm/cold upgrade preserves exact identity/history/files/
   drafts/queued-send fixtures; test corrupted-profile recovery and update
   recognition on the packaged candidate. Record acceptance for every selected
   B/F item and the actual Q coverage; unresolved blocking failures or required
   unavailable coverage need an explicit owner disposition, never an assumed
   waiver. No release while B1/B2 remain open. Relay rollout requires its
   applicable owner approval and verified stopped-state
   backup/data/configuration/realm/neighbor preservation. Keep claimed physical
   results distinct from CI and emulator results.
8. Update Linear and release records with exact source/artifact evidence. Remove
   only completed merged task branches/worktrees, stop owned fixtures and leave
   both repositories clean and pushed.
