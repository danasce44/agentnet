# v0.8.19 — Android in every release

Status: implementation and focused verification, not published.

Sergey requested a published APK built by release CI, rather than a local
Downloads artifact. v0.8.18 remains immutable. This release integrates the
existing native Android branch and fixes its updater (MEL-551). No new sync
architecture or feature batch is in scope.

The preview's Update now button called `/api/app/update` on the Android
loopback UI server. That route belongs to the desktop shell and did not exist
on Android, producing the reported 404 before any download. Separately, the
published releases contained no APK. Both failures must be fixed.

## Contract and ownership

- Root owns integration, release workflow, verification, publication and the
  existing relay deployment. Android build helper owns Kotlin/manifest/Gradle;
  Android core helper owns the native JS bridge and existing Comic controls.
  An independent GPT-6.1-sol reviewer checks the integrated updater.
- Preserve the existing `.preview` package and original signing certificate;
  an in-place update keeps identity, messages, queued sends, attachments and drafts.
- Kotlin downloads only the fixed official GitHub release and exact
  `AgentNet-android.apk` named in its SHA256SUMS. Check the APK's package,
  original signing certificate and exact newer version before Android's
  standard installation confirmation. Caller-supplied URLs/paths are refused.
- Existing Comic Check for updates and Update controls use the native bridge.
  Missing assets, offline failures and canceled installation remain truthful
  and retryable. No desktop-only CLI controls on Android.
- The tagged release workflow must build both arm64 and x86_64 in one signed,
  nondebuggable APK, verify signing/version and 16KiB compatibility, and require
  that artifact before assembling the draft and SHA256SUMS. Missing signing
  material fails the build; never regenerate the established signing key.
- This is a GitHub-distributed preview. Self-install permission is confined to
  the preview/debug variants. A future Play distribution uses Play updates.
- Under the owner's latest-only relay policy Android needs a matching APK on
  each release. The old preview needs one manual installation of the published
  APK because its broken update bridge cannot repair itself.

## Gates

1. Focused bridge, rendered Comic desktop/mobile, native policy/unit/lint and
   packaged APK checks; then independent review.
2. Owned emulator update and cold restart preserving all 203 exact fixture
   messages, queued sends, attachment, draft and identity; installer permission,
   cancellation/retry and completed update. No user device mutation.
3. Integrated source vet, all required race partitions, affected native
   platform checks and real mixed-version gate against published v0.8.18.
   Retain valid unchanged evidence; do not repeat full suites per bug.
4. Tag-built draft APK, all thirteen asset digests and twelve manifest entries,
   original certificate and exact tag version; publish only after qualification.
5. Deploy only the existing relay through its stopped-state backup and verified
   update workflow. Clients update themselves. Record actual evidence here.

Physical owner-phone timing and camera decoding remain unverified until tested
there. Emulator evidence is not a claim of physical arm64 execution or Play
approval. Existing MEL-546/558 stay open for those outcomes.
